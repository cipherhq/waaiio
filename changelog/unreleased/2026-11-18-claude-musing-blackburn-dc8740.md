## 2026-11-18 — Admin "Onboard Customer" asks for the same required fields as Get Started

- **Owner request (2026-11-18):** "for onboarding customers can you make the required fields request just as how it is in getting started". The screen is the admin panel's **Onboard Customer** page (`/customer-onboarding`), which posts to `POST /api/admin/onboarding`.
- **Change (new requests only):**
  - **WhatsApp Name** (the bot code) is now required, as in Get Started: label "Your WhatsApp Name", the same explanation text, cleaned up as it is typed (upper case, spaces to dashes, letters, numbers and dashes only, 30 characters), at least 2 letters or numbers. It was "Bot code (optional)".
  - **At least one feature** must be ticked, as in Get Started ("Please select at least one feature to continue"). An empty choice no longer falls back to category defaults on create.
  - **Business phone** must be the full number, as Get Started's phone field produces it: the country dialing code followed by exactly that country's `countries.phone_digits` digits. Spaces, dots, dashes and brackets are ignored and removed. The page shows the expected format under the field.
  - A **taken WhatsApp Name** is rejected before the invite record or the owner's account is created, with Get Started's message ("Bot code is already taken. Please choose a different one."). Before, a taken custom code failed after creation and left a failed queue record.
  - The review step shows the WhatsApp Name.
- **Files:** new `shared/onboarding-fields.ts` (clean-up, phone check and messages, used by both apps); `lib/onboarding/admin-assisted.ts` (`validateAdminOnboardingInput(..., { newRequest: true })` adds the checks); `app/api/admin/onboarding/route.ts` (create passes `newRequest`; options now include `phone_digits`); `admin/src/pages/CustomerOnboarding.tsx`.
- **Unchanged:** Get Started and `/api/onboarding/register`; payments and fees; no migration. Retry of a failed queue record re-checks its stored input with the earlier rules, so requests saved before this change can still be retried. Owner phone stays optional (Get Started has no such field). Terms and privacy consent stay with the customer at activation.
- **Tests:** new `lib/__tests__/admin-onboarding-required-fields.test.ts` (real create route: missing/short WhatsApp Name, no feature, wrong phone shapes, taken name — each 400 with no invite or account created; complete request saves the cleaned name and phone; retry keeps the earlier rules). New `admin/src/__tests__/customer-onboarding-required-fields.test.tsx` (rendered page: required field and explanation, clean-up, each stop message, phone length from options, complete payload, taken-name server message). Existing `admin-onboarding-get-started-parity.test.ts`, `customer-onboarding-551.test.tsx` and `customer-onboarding-address-capabilities.test.tsx` now fill the WhatsApp Name and a feature.
- **Could break:** an admin who used to leave the bot code or features blank, or typed a local phone number (e.g. `080…`), now has to complete them. A country whose `phone_digits` is wrong in the database rejects valid numbers here, as Get Started already does.
