## 2026-11-18 — Tighten admin panel database access (M549)

- **Change (M549 `supabase/migrations/549_admin_access_tightening.sql`):**
  - `admin_role_permissions`: every admin role still reads it (menu gating in `admin/src/hooks/usePermissions.ts`); writes are now limited to full admins (`is_admin()`, aal2) with separate INSERT/UPDATE/DELETE policies. anon has no rights. No admin page writes this table today.
  - `payout_accounts` and `business_bank_accounts`: new stored generated column `account_number_last4`. Browser sessions (`authenticated`) get an exact column grant that includes `account_number_last4` and not `account_number`; server routes (service role) keep the full number for transfers. Pages that showed `****1234` now read the last four directly: admin `Payouts` (approve modal), `Businesses`, `ImpersonationMode`; merchant `app/dashboard/payouts/page.tsx`.
  - `public.get_effective_commercial_config()` is dropped. The admin Countries page loads the effective config from a new `GET` on `app/api/admin/countries/messaging-config/route.ts` (full admin, aal2; version chosen by the DB clock via `get_effective_config_version_id()`, then read by id). CORS for that route now allows GET.
- **Unchanged:** payout approval and mark-paid (the approve route reads the destination with the service role), Paystack/Stripe transfers, merchant bank-account API, the bot's bank-transfer details, messaging config saving (still step-up), the four admin roles' read access.
- **Tests:** `lib/__tests__/admin-access-tightening-549.pg.test.ts` (real PostgreSQL, two starting grant states, M549 applied twice: role matrix for the permission table, masked columns per role, service role keeps the full number, exact grants, function gone; wired into the security-acl-tests job). `lib/__tests__/admin-commercial-config-route-549.test.ts` (route: admin only, DB-clock version, errors, CORS, POST still needs step-up). `admin/src/__tests__/account-number-masked-549.test.tsx` (rendered approve modal shows `****6789`; every browser read selects only the masked column). Updated: `countries-messaging-controls`, `countries-stripe-plan-refs-762`, `businesses-resource-parity-762` (mock the route / masked column).
- **Could break:** during a release, between the migration and the new admin/merchant deploy, old pages that still ask for the full account number or call the dropped function get an error (payout account details and the Countries messaging section fail to load until the deploy). Anything else reading `account_number` from these tables in the browser would now be refused; none was found.
